# AI 岗位匹配分析器

> 上传简历 + 粘贴岗位 JD，自动计算加权匹配度、定位关键词缺口、给出可执行的简历改进建议。

一个面向「AI 应用开发 / 软件开发」求职场景的小工具。核心匹配逻辑完全本地运行，
不依赖任何外部服务；大模型仅用于把计算结果翻译成自然语言的改进建议。

---

## 功能特性

- **简历解析**：支持 PDF / DOCX / TXT / MD，也支持直接粘贴文本
- **关键词加权匹配**：不是简单数关键词个数，而是根据 JD 中的修饰词
  （「精通 / 必须」→ 权重 ×1.5，「了解 / 加分」→ 权重 ×0.6）和出现频次动态计算权重
- **「或」关系识别**：JD 里写「熟悉至少一种后端框架（Flask / FastAPI / Django）」时，
  程序知道这三个是**可替代**的，命中任意一个即视为满足，不会把可选项当成三条缺失
- **硬门槛判定**：自动识别学历要求与经验年限要求，不符合时给出明确提示并计入扣分
- **双轨建议输出**：优先调用大模型生成建议；未配置 API Key 或网络异常时，
  自动回退到规则引擎生成的建议，功能不中断
- **零依赖演示**：核心打分不联网即可运行，适合现场演示

## 快速开始

```bash
# 1. 安装依赖
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt

# 2. 启动服务
python app.py

# 3. 打开浏览器
#    http://127.0.0.1:5000
```

不想开网页也可以用命令行看效果：

```bash
python demo.py                                  # 用内置样例
python demo.py 我的简历.docx JD.txt              # 用指定文件
```

## 配置大模型（可选）

不配置也能正常使用，只是改进建议由规则模板生成。

配置后建议质量会明显提升。推荐使用智谱开放平台的免费模型：

1. 打开 <https://open.bigmodel.cn>，用手机号注册（免信用卡）
2. 进入「API Keys」页面，新建并复制密钥
3. 填入 `config.json`：

```json
{
  "llm": {
    "api_key": "你的密钥",
    "base_url": "https://open.bigmodel.cn/api/paas/v4",
    "model": "glm-4.7-flash",
    "timeout": 60
  }
}
```

**更安全的做法**：不把密钥写进文件，改用环境变量（优先级高于配置文件）：

```bash
set ZHIPU_API_KEY=你的密钥        # Windows 当前会话
setx ZHIPU_API_KEY "你的密钥"     # Windows 永久生效
```

由于调用的是 **OpenAI 兼容**格式接口，只要修改 `base_url` 和 `model`，
就能切换到通义、DeepSeek、腾讯混元等其他平台，业务代码无需改动。

## 设计说明

### 为什么把「匹配打分」和「大模型」分开

这是本项目最重要的一个设计决策。常见的做法是把整段文本丢给大模型，
让模型直接给一个匹配度分数。这样有两个问题：**分数不可复现**、**无法解释**。

本项目的做法是：

| 环节 | 实现方式 | 特点 |
|---|---|---|
| 关键词提取与加权打分 | 本地规则引擎 | 确定性、可复现、每一分都能解释 |
| 门槛判定（学历 / 经验） | 正则 + 词典 | 同上 |
| 自然语言改进建议 | 大模型（可选） | 灵活、有表达力，但允许失败 |

这样一来，即使大模型完全不可用，工具的核心功能依然完整。

### 匹配度计算方式

```
加权匹配度 = 命中技能的权重之和 / JD 要求技能的权重之和 × 100%

单项权重 = 1.0
         + 重复出现次数加成（每次 +0.3，上限 +0.9）
         × 修饰词系数（强要求 ×1.5 / 弱要求 ×0.6）
         × 类别系数（软性要求 ×0.5，因为软技能不是简历筛选的硬指标）

最终得分 = 加权匹配度 - 门槛扣分（学历不符 -25，经验不符 -15）
```

### 已处理的边界情况

- 扫描件 PDF 无法提取文字 → 明确提示改用粘贴文本或换格式
- 老版 `.doc` 文件 → 提示另存为 `.docx`
- JD 文本过短、无法识别关键词 → 给出明确说明而不是返回 0 分
- API Key 未配置 / 失效 / 触发限流 / 断网 → 逐类给出提示并自动降级
- 短英文缩写误匹配 → 对长度 ≤ 2 的别名（`js`、`ts`、`go`）加词边界校验，避免 `js` 命中 `json`

## 已知局限

- 技能词典是人工维护的，覆盖常见技术栈但不完整，遇到冷门技术可能识别不到
- 无法理解语义近似，例如简历写「页面重构」而 JD 写「前端优化」时不会自动关联
- 中文分词未引入专业分词库，长尾关键词的召回率有限
- 分数是相对参考值，不代表用人单位的真实筛选结果
